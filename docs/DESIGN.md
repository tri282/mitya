# Mitya — Architecture Overview

Goal: A local LLM that writes like Fyodor Dostoevsky and answers grounded in his 5 novels, on a single 6GB GPU.  
*Requirements: Mistral-7B QLoRA fine-tune (done); metadata-tagged RAG over the novels (designed, pending implementation); GPU budget ≤ 6GB; all retrieval on CPU.*  

Mitya splits into two independent subsystems: **Style** (a Dostoevsky-voiced fine-tune) and **Substance** (RAG grounding over the actual texts). The two compose at generation time — RAG supplies passages, the fine-tuned model answers in character, and citations are shown programmatically rather than asked of the model. Every design choice in both subsystems is bounded by a single 6GB consumer GPU.

---

## I. System Overview

```txt
OFFLINE                                    ONLINE
--------                                    ------
PDFs -> OCR -> chunk -> synthetic Q&A       llama-server (Mitya GGUF, GPU)
  -> QLoRA fine-tune -> merge -> GGUF              ^
  (src/ingestion.py, src/training.py,              | persona + context prompt
   scripts/build_dataset.py, quantize.sh)          |
                                             src/api/app.py (FastAPI, SSE)
Dostoevsky .txt corpus -> per-book parse           ^
  -> chunk -> embed -> Qdrant upsert                | query
  -> entities.json / summaries.json           router -> retrieve -> rerank
  (src/rag/ingest.py, scripts/build_*.py)      (src/rag/*, CPU only)
```

Offline work produces two static artifacts: the quantized GGUF model and the Qdrant collection + entity/summary JSON. Online, a query is routed, retrieved and reranked entirely on CPU, then handed to `llama-server` — the only GPU consumer — for in-character generation.

---

## II. Part 1 — Style (fine-tune)

* Base model `unsloth/mistral-7b-instruct-v0.3-bnb-4bit`, fine-tuned with **QLoRA** via **Unsloth** (`SFTTrainer`/`trl`).
* Training data: synthetic Q&A generated by a teacher LLM (Gemini/Ollama) from OCR'd novel chunks — a question-generation pass, then an answer pass in Dostoevsky's first-person voice, formatted as **ChatML** (system/user/assistant).
* Merge LoRA adapters into the base (`merge_and_unload()`), quantize via `llama.cpp` to `q4_k_m` / `q5_k_m` (also `q8_0`).
* **Status: done.** Model exists and runs via `scripts/start_chat.sh`.

*See `docs/FINE_TUNE.md` for the full pipeline.*

---

## III. Part 2 — Substance (RAG)

High-level pipeline (settled design, not yet built):

* Clean-plaintext corpus (`data/rag/*.txt`, no OCR) — one novel per file.
* Per-book structural parser emits chunks plus a `structure.json` manifest (book/part/chapter tree), since heading formats differ per book.
* Ingest to **Qdrant** (local mode): hybrid dense (`nomic-embed-text-v1.5` via fastembed) + sparse (BM25 via fastembed, IDF-weighted), fused server-side with Qdrant's **native RRF**.
* **FlashRank** reranks the fused top-25 down to top-3.
* An **entity map** (`entities.json`, teacher-LLM + human review) resolves query terms to canonical names/aliases and expands the query text before embedding — not a Qdrant `should`-boost.
* A deterministic **DEFAULT | STRUCTURAL** router: STRUCTURAL only when a summary-intent keyword *and* a resolvable chapter scope both hold (backed by pre-generated `summaries.json`); everything else is DEFAULT hybrid retrieval.
* Generation is **single-pass**: the fine-tuned persona answers in character from the retrieved passages, with a **programmatic Sources list** appended after the stream — no inline citations.
* **Status: designed, not built.**

*See `docs/RAG.md` for the settled design and `docs/superpowers/specs/2026-07-13-rag-decisions.md` for the rationale.*

## IV. How the two compose

RAG retrieves passages; the fine-tuned model never saw retrieved context during training and its persona explicitly refuses references to external sources. Rather than fight that conditioning with citation instructions, the system prompt keeps the fine-tuned persona text verbatim and frames the passages as the author's **own recollections** — first-person-compatible, and aligned with (not against) the "no external references" training. Grounding is shown to the user as a **programmatic Sources list**, built from retrieval metadata after generation completes, independent of whether the model cooperates. See `docs/RAG.md` §III.4 for the exact prompt composition.

---

## V. Hardware Budget

The 6GB GPU runs **only** the quantized LLM (`q4_k_m`, ≈5.2–5.5GB total with KV cache and compute buffers); every retrieval component (embedding, BM25, Qdrant, reranking) runs on CPU, and within a request the two phases are sequential, so there is no GPU contention. See `docs/RAG.md` §V for the full arithmetic and the `llama-server` launch flags.
